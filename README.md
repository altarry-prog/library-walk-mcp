## 로컬 재현

Python 3.14에서 검증한 패키지입니다. 패키지 폴더에서 실행합니다.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python verify_server.py
.venv/bin/python planner.py --request data/example_request.json
```

Windows의 실행 파일 경로는 `.venv\Scripts\python.exe`입니다. Windows에서는 별도 실행 확인이 필요합니다.

`verify_server.py`는 시험 인증값을 메모리에서 만들고 로컬 서버를 띄워 검사한 후 종료합니다. 실제 인증키·정보나루·모델 호출은 필요하지 않습니다. 이 스크립트가 재생성하는 파일은 실행 기록과 모의 응답입니다.

서버를 계속 실행하려면 운영 환경의 비밀값 관리 기능으로 `MCP_ACCESS_TOKEN`을 설정한 뒤 다음을 실행합니다. 인증값은 공백 없는 ASCII 32~256자의 충분히 긴 임의 값이어야 합니다. 실제 값은 파일·명령 인자·지시문·채팅에 쓰지 않습니다.

```sh
.venv/bin/python server.py
```

기본 주소는 로컬 루프백의 8000번 포트입니다. 이것은 외부 FabriX에서 접근할 수 있는 주소가 아닙니다. 서버는 운영체제 환경변수만 읽습니다. `.env.example`은 Docker용 비밀이 아닌 설정 견본이며, 인증값을 넣는 파일이 아닙니다.

- 대회·기관에서 읽기 전용 외부 MCP 연결을 허용하는지 확인.

- FabriX 테넌트에서 지원하는 전송 방식·인증 방식·도구 연결 가능한 Agent 유형 확인.
- 승인된 실제 자료의 출처·시간·기관 번호·이용조건 대조.

이 단계들은 코드가 존재한다는 이유만으로 완료되지 않습니다.

## 기본 안전 상태

외부 실호출은 꺼져 있습니다. 정보나루 키는 `NARU_KEY` 환경변수로만 읽습니다. `EXTERNAL_LINK_APPROVED`와 `ALLOW_LIVE_CALLS`도 켜져 있어야 하지만, 이 설정값 자체가 기관 승인 증명은 아닙니다. 모의자료 상태에서는 실호출을 켤 수 없습니다.

신청·예약·삭제·쓰기 도구는 없습니다. 정보나루는 하루 전 기준이며 현재 상태를 보장하지 않습니다. 프로그램 정원은 남은 자리가 아닙니다. 공간 정보와 시간별 빈자리는 다릅니다. 서버 로그를 줄였지만 플랫폼·호스팅의 기록 정책까지 없어지는 것은 아닙니다.

현재 인원·대상·요금 검사는 정규화한 항목에 한정됩니다. 상세 연령·거주지·회원·우선접수 자격 등은 자동으로 입증하지 않습니다. 다른 시설 간 이동시간, 여러 프로그램의 긴 일정, 자동 예약은 이번 구현 범위가 아닙니다.

이전 중간본의 시험·진행 기록은 이전 ZIP의 기록입니다. 이 판의 파일 목록·해시·시험 범위는 `MANIFEST_0.2.json`과 `VERIFICATION.md`를 기준으로 봅니다.
