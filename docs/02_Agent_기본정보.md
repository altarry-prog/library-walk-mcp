# FabriX 기본정보: 「도서관 산책」 모의 시범판 (0.3)

FabriX Agent 생성 ① 기본정보 설정과 ② 역할 설정에 붙이는 글입니다. 글자 수 한도(이름 50, 설명 2,000, 사용 방법 2,000)는 11. 5. 실제 화면에서 확인했습니다.

## 이름
도서관 산책

## 설명
사서·문화업무 담당자가 이용자의 취향과 날짜·시간·인원·예산·필요 시설 조건을 입력하면, 연결된 자료 범위에서 읽을 책, 들러 볼 강좌·행사, 머물 자리를 한 시설 안에서 시간이 이어지는 하루 코스로 짜고 안내문을 만듭니다. 현재 기본 자료는 전부 가상입니다. 실제 신청·예약은 하지 않으며 실제 도서관의 공식 서비스가 아닙니다.

## 모델·역할
- 대화모델: 베이스모델 Solar Pro 4(테넌트 기본값). 세션3 지정 모델.
- 지시문: 프레임워크 Custom을 고르고 `03_Custom_지시문.txt` 전문을 붙입니다.
- Temperature 0.2는 시험 시작값 제안입니다. 공식 요구나 검증된 최적값이 아니며 「[고급] 모델 설정」에서 지원 범위를 확인합니다.
- Knowledge: 비웁니다. 이 Agent는 도구(MCP)로 자료를 읽습니다.
- Tools: 「MCP Server 추가」에서 승인·배포된 「도서관 산책 읽기전용」를 선택합니다.

## 예시 질문: 최대 4개

1. 모의자료로 2026년 11월 7일 13~17시, 우주를 좋아하는 가족 4명의 계획을 만들어 줘. 예산은 총 2만 원, 프로그램 후 공간 이용은 60분이야. 계단 없는 접근이 필요하고, 미확인 조건이 있는 후보는 빼 줘.
2. 모의자료로 2026년 11월 7일 14~17시, 우주를 좋아하는 가족 4명의 계획을 만들어 줘. 총 2만 원 안에서 프로그램 후 공간을 60분 쓰고 싶어. 별도 시설 조건은 없고, 미확인 후보는 빼 줘.
3. 모의자료로 2026년 11월 7일 13~17시, 우주를 좋아하는 가족 4명이 프로그램과 60분 공간 이용을 원해. 확인된 비용은 0원 이하여야 하고 계단 없는 접근이 필요해. 미확인 후보는 별도로 보여 주되, 무료나 예약 가능으로 확정하지 마.
4. 도구로 현재 자료의 모의 여부·지원 지역·자료 날짜를 확인하고, 전국 실시간 조회나 실제 예약이 가능한지 정확히 설명해 줘.

예시의 2026. 11. 7.은 가상 시연 날짜입니다. 실제 운영용 예시로 바꿀 때에는 승인된 자료에 맞게 날짜와 범위를 다시 작성합니다.

## 사용 방법

지역·날짜·시간대·취향·인원·예산·공간 이용시간·필요 시설 조건을 알려 주세요. 이름·회원번호·연락처·정확한 집 주소는 넣지 마세요. 모르는 조건은 먼저 확인합니다. 가상 자료의 결과는 실제 이용 가능한 장소나 프로그램이 아닙니다. 자료가 없거나 미확인인 부분은 그대로 남깁니다. 실제 신청과 예약은 공식 경로에서 사람이 확인합니다.

## 첫 시연의 기대값

첫 예시의 조건을 그대로 도구에 전달하면 가상도서관 A의 1코스 책·2코스 프로그램·3코스 공간 후보가 나옵니다. 모의 프로그램 13~14시, 모의 공간 희망 이용 14~15시, 등록된 모의 이용료 합계 5,000원입니다. 로컬 도구 결과와 맞출 기준이며 **Solar Pro 4가 실제로 이렇게 답했다고 검증한 기록은 아닙니다.** 서버 미연결 상태의 첫 시험(11. 5. 15:11)에서는 자료를 지어내지 않고 「확인할 수 없다」로 답했습니다.

## MCP Server ① 기본 정보에 붙이는 글

### 이름
도서관 산책 읽기전용

### 설명
「도서관 산책」 Agent가 쓰는 읽기 전용 도구 서버입니다. 등록된 자료에서 책·문화프로그램·공간을 찾고, 날짜·시간·인원·예산·필요 시설 조건을 대조해 이용계획 후보를 만듭니다. 신청·예약·결제·삭제 같은 쓰기 기능은 없습니다. 현재 자료는 전부 가상(모의)이며 실제 시설·행사·빈자리가 아닙니다. 정보나루 조회 도구 3개는 기본으로 꺼져 있습니다. 실제 도서관의 공식 서비스가 아닙니다.

### 사용 방법
1) 대화를 시작할 때 get_data_status로 자료 상태(모의 여부·지역·자료 기준일)를 먼저 확인합니다. 2) search_resources는 kind(books, programs, spaces)를 정해 등록 자료를 찾습니다. 3) 조건이 정리되면 make_visit_plan에 request 객체를 넘깁니다. 키: region, date(YYYY-MM-DD), start_time·end_time(HH:MM), topic, audience, group_size, space_minutes, budget_krw, needs(문자열 배열), allow_unknown(기본 false), limit(기본 3). 4) 결과의 미확인 표시(total_fee_krw가 null, slot_evidence가 requested_not_verified 등)는 확정으로 바꾸지 않습니다. 5) search_books_live·find_holding_libraries_live·check_book_status_live는 기본 비활성입니다.
