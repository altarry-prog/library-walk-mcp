# 전국 확장 상세설계

상태: **설계안**. 전국 API·전국 도서관·실시간 예약을 구현·확보했다는 보고서가 아닙니다. 현재 구현은 별도 시제품 0.2이며 같은 시설의 책·프로그램·공간을 등록자료에서 대조합니다.

## 1. 목표와 이용자

공무원·사서가 시민의 비식별 요청을 입력해 생활권 안의 책·배움·모임 공간을 함께 제안하는 업무지원으로 시작합니다. 장기적으로 시민용 서비스로 확장할 수 있으나, 정부 업무망의 Agent를 그대로 대국민 서비스로 공개하는 것은 별도 승인·인증·접근 환경 검토가 필요합니다.

차별점은 API 수가 아니라 ‘조건을 함께 맞추는 과정’입니다. 취향이 맞아도 기간이 지난 행사, 인원이 맞지 않는 공간, 예산을 확인하지 못한 조합을 구분하고, 조건 변경 시 계획을 다시 계산합니다. 이용률·만족도·업무시간 개선은 현재 미측정인 가설입니다.

## 2. 목표 구조와 현재 구현의 차이

| 계층 | 현재 구현 | 전국 확장 시 추가할 것 |
| --- | --- | --- |
| 대화 | FabriX용 Custom 지시문 작성 | 실제 모델·지역명·상대 날짜 해석·질문 방식 시험 |
| 도구 | 인증된 MCP 6개, 읽기 전용 | 기관별 권한·분산 요청량·운영 감시 |
| 조건 대조 | 같은 시설, 프로그램 1개 후 공간 1개 | 여러 시설·여러 활동·이동 조건. 검증 전 도보시간 추정 금지 |
| 자료 | 가상 자료, 고정 JSON 읽기, 부천 CSV 변환기 | 승인된 지역별 수집·정규화·중복 조정·기관 연결 |
| 도서 API | 정보나루 선택적 어댑터, 실호출 기본 비활성 | 실제 응답·권한·공동 한도·날짜 기준 확인 |
| 프로그램 | 고정자료 지원 | 제공기관별 일정·실제 회차·대상·신청 상태 연결 |
| 공간 | 고정자료 지원 | 공개 가능 시간대·이용 자격·요금 정책 연결 |
| 운영 | 단일 프로세스 보조 제한·메모리 캐시 | 공통 캐시·분산 한도·자료 버전·관리자 검토·장애 기록 |

현재 서버의 JSON 카탈로그에 전국 자료를 무제한으로 넣는 방식으로 확장하지 않습니다. 먼저 지역·날짜·주제로 후보를 좁힐 수 있는 자료 저장소·조회 계층을 둡니다. MCP에는 좁힌 후보와 근거·상태만 전달합니다.

## 3. 자료 제공자별 연결 계약

`data/provider_registry.json`은 조사·구현 상태를 기록한 표이지 실제 API 설정 파일이 아닙니다. 미확인 주소를 임의로 만들어 넣지 않았습니다.

각 제공자는 다음 항목을 확인한 뒤 연결합니다.

- 제공기관·자료명·공식 상세 페이지·이용조건·승인 방식.
- 지원 지역·시설 종류·포함/제외 범위. ‘전국’ 표제와 실제 참여기관 범위를 구분.
- API·CSV·승인된 고정자료 중 방식, 필수 인증정보, 요청량, 응답시간 제한.
- 자료 기준일·원 제공자 갱신시각·우리 조회시각. 조회시각만 바꾸어 최신 자료처럼 보이지 않게 함.
- 오류·빈 응답·지원하지 않는 항목의 표현, 개인정보 필드 여부.
- 출처 링크·수정 이력·이용 종료 시 삭제 범위·재배포 조건.

연간 CSV의 자동 변환 API를 매분 호출해도 실시간 자료가 되지 않습니다. 자료 형식과 최신성은 별개입니다.

## 4. 기관과 자원 식별

기관 이름만으로 합치지 않습니다. 같은 이름의 도서관·분관·복합문화시설이 있을 수 있습니다.

- 내부 공통 시설 ID와 정보나루 도서관 번호, 지자체 시설 ID, 공유누리 자원 ID를 별도 연결표로 관리합니다.
- 기관·공개 주소·공식 상세 페이지·공식 번호를 대조하고 사람이 승인한 연결만 활성화합니다.
- 프로그램이 도서관 밖 장소에서 열리면 운영기관과 실제 장소를 분리합니다.
- 미확인 연결은 검색 후보로만 보여 주거나 보류합니다. 같은 시설에서 가능한 계획으로 합치지 않습니다.
- 지역번호·시설번호는 자료 설정에 두고 코드에 박아 넣지 않습니다. 현재 `DEMO`와 `MOCK-*`는 가상 시험 식별자입니다.

## 5. 정규화할 자료

| 자료 | 최소 확인 항목 | 모르면 어떻게 하나 |
| --- | --- | --- |
| 공통 | 제공기관·원 ID·시설 ID·출처·기준일·조회시각·지역 | 출처·시설 연결이 없으면 실제 계획 확정 금지 |
| 도서 | ISBN·서명·관련 주제·소장 도서관·상태의 기준 시점 | 현재 대출 가능으로 바꾸지 않음 |
| 프로그램 | 실제 회차 날짜·시각·대상·접수 상태·비용 | 기간을 매일 개최로 확장하지 않음. 시각 없으면 시간표에 넣지 않음 |
| 공간 | 시설·인원·설비·공개 시간대·요금·이용 자격 | 빈자리·용량·요금을 0이나 가능으로 채우지 않음 |

프로그램의 정원·객석수·신청 인원·남은 자리는 다른 항목입니다. 계산에 필요한 값과 운영 규칙이 모두 확인된 경우에만 파생값을 만들고 계산식을 남깁니다.

프로그램의 ‘아동’ 같은 넓은 대상 구분만으로 학년·거주지·회원 자격까지 확인한 것으로 보지 않습니다. 현재 시제품도 이 세부 자격은 별도 확인 사항으로 남깁니다.

## 6. 추천과 조건 대조

1. 모델이 사용자가 직접 밝힌 취향·조건을 구조화합니다. 민감한 속성을 추정하지 않습니다.
2. 지역·날짜로 자료를 좁히고 주제에 맞는 책·프로그램을 찾습니다.
3. 실제 시설 연결을 확인한 뒤 인원·운영시간·기간·대상·알려진 비용을 대조합니다.
4. 미확인 조건이 없는 후보와 조건부 후보를 나눕니다. 현재 상태가 보장된다는 뜻은 아닙니다.
5. 조건부 후보는 사용자가 보고 싶다고 할 때 별도로 표시합니다.
6. 후보를 추천한 이유·제외한 이유·공식 확인 경로를 제공합니다.
7. 사용자가 조건을 바꾸면 다시 계산합니다. 바뀌지 않은 조건은 유지합니다.

예산 부족·거리·프로그램 우선순위가 충돌할 때에는 선택지를 보여 줍니다. 필수 접근성·인원·대상 조건을 임의로 완화하지 않습니다. 적합한 조합이 없다는 답도 정상 결과입니다.

향후 다른 시설 간 계획에는 지도·교통 자료의 이용조건과 계산 근거가 필요합니다. 좌표에서 구한 직선거리를 도보시간으로 바꾸지 않습니다. 이동 자료가 없으면 동일 시설·동일 생활권 후보까지로 한정합니다.

## 7. 갱신·장애·요청량

- 정보나루 공동 한도를 기존 세션1 서비스와 분리해 검토합니다. 키 개수나 단순 교체로 처리량을 보장하지 않습니다.
- 도서의 하루 전 상태, 행사 정기 갱신, 공간 시간대 조회의 성격에 맞는 재사용 시간을 각각 정합니다. 제공자가 허용한 범위에서만 자동 갱신을 검토합니다.
- 현재 코드의 `MAX_NARU_CALLS_PER_PROCESS`는 재시작하면 초기화되는 보조 제한입니다. 여러 서버의 공통 한도 관리가 아닙니다.
- 확장 시 한도 카운터·동일 요청 합치기·잠시 대기·재시도 상한을 공동 관리합니다. 실패 시 무한 재시도하지 않습니다.
- 출처가 실패하면 해당 부분을 ‘확인 못 함’으로 표시합니다. 빈 목록과 장애를 구분합니다.
- 과거 정상 자료를 재사용할 때에는 원래 기준일·수집시각·고정자료 상태를 유지합니다. 빈자리를 과거 값으로 확답하지 않습니다.
- 생존 점검은 `/health`와 초기화·도구 목록으로 제한합니다. 실제 제공기관·모델을 계속 호출하는 감시는 승인 없이 만들지 않습니다.

이번 작업에서 새 예약 자동화나 주기적 외부 호출을 등록하지 않았습니다.

## 8. 권한·보안·개인정보

현재 구현은 정적 Bearer 인증이며 기관용 OAuth·사용자별 권한 체계가 아닙니다. 전국 운영 전에는 기관별 접근 범위·자격증명 회수·로그 보관·부하·취약점 대응을 검토해야 합니다.

이용자 이름·회원번호·연락처·정확한 집 주소는 입력 항목으로 받지 않습니다. 필요한 시설 조건만 받습니다. 자유 입력과 플랫폼 기록에 개인정보가 남을 가능성까지 지시문만으로 없앨 수 있다고 주장하지 않습니다.

키는 서버 환경변수·비밀값 관리 기능으로만 다룹니다. 사용자 입력에 임의 URL·명령·파일 경로를 받아 실행하는 도구를 만들지 않습니다. 외부 자료 속 지시는 명령으로 취급하지 않습니다. 운영 도서관리시스템·누리집 로그인·SSO에 접속하거나 자동화하지 않습니다.

개인 예약 내역이 아니라 공개 가능한 자원 시간대 정보만 대상입니다. 실제 접수·예약은 이번 범위에서 제외하며, 향후 필요하면 별도 기관 승인·본인 확인·권한·취소·감사 체계를 먼저 설계합니다.

## 9. 확장 단계와 완료 기준

| 단계 | 범위 | 다음 단계 조건 |
| --- | --- | --- |
| A 현재 | 가상 자료와 연결 준비 패키지 | 로컬 시험·설정 점검, 플랫폼 실제 연결 확인 |
| B 첫 생활권 | 확보한 기관의 승인된 실제 자료 | 실제 회차·기관 연결·자료 시점·권한·미확인 처리 확인 |
| C 이질적인 지역 추가 | 서로 다른 제공 형식의 지역을 추가하는 시범 | 공통 로직을 고치지 않고 어댑터·설정으로 적용 가능한지 기록 |
| D 전국 제공기관 연결 | 참여·공개 범위에 따른 확장 | 지역별 지원 범위·오류·갱신·비용·담당자 체계 운영 |

‘전국 완료’라는 단일 표시 대신 지역별 도서·프로그램·공간·시간대의 지원 범위를 보여 줍니다. 전국의 모든 도서관을 분모로 삼으려면 먼저 기준일과 대상 시설 목록을 정해야 합니다. 연결한 자료 건수만으로 전국 보급률을 만들지 않습니다.

## 10. 운영 역할·비용·성과 확인

- 업무 담당자: 유용한 요청 유형·필수 조건·안내문과 실제 이용 가능성 확인.
- 자료 담당자: 원자료·갱신·기관 연결·이용조건 승인.
- 시스템 담당자: 서버·인증·비밀값·공통 한도·장애 대응.
- 제출 담당자: 대회 허용·배포판·심사 열람·설명서 일치 확인.

비용은 서버·도메인/TLS 운영·모델 사용·자료/API·지도·로그·보안·사람의 자료 정비 시간을 나눠 견적받습니다. 현재 확인하지 않은 월요금을 만들지 않습니다. 무료 공개 데이터라고 총 운영비가 없는 것은 아닙니다.

성과는 같은 업무·같은 종료점으로 측정합니다. 조건 위반·가짜 확답·출처 누락·담당자 재작업·자료 노후화·연결 실패를 각각 기록합니다. 기존 책이지의 시험 수나 직원 C 측정을 이 에이전트의 성과로 옮기지 않습니다. 실제 도입·이용률·만족도는 측정 전까지 미측정으로 둡니다.
